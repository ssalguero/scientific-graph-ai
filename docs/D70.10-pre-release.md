## 1. Resumen ejecutivo

**D70 — Restore Points Foundation** entrega la infraestructura desacoplada de **Restore Points nombrados** sobre Session Snapshots (D69): Factory · Registry (Map SSOT) · Serializer/Deserializer con schema version · barrel aislado · **sin** Provider wiring, **sin** UI, **sin** historial visual / timeline / undo / versionado / branching / diff (D71+).

Compatible con Freezes D65–D69 **sin refactor** de Registry, Persistence, Restore, Autosave, Snapshots ni Context públicos.

Documentación de certificación completa. Suite `validate:d70-gate` en verde. Proyecto listo para **D70.11 — CA Official** y **D70.12 — Release**.

---

## 2. Arquitectura final

```text
Caller
  → createRestorePoint(options)
        → createSessionSnapshot(..., SnapshotReason.RESTORE_POINT)  // D69
        → wrap RestorePoint { id, name, description?, createdAt, origin, snapshot, metadata }
  → RestorePointRegistry (Map SSOT · create/get/remove/clear/list/count)
  → serializeRestorePoint / deserializeRestorePoint
        → serializeSessionSnapshot / deserializeSessionSnapshot  // D69
        ✗ no IndexedDB · no SessionRegistry · no Provider
```

**SessionSnapshot permanece el dueño del estado serializado.** Restore Point solo agrega identidad nombrada + metadata.
