## 1. Resumen ejecutivo

**D70 — Restore Points Foundation** introduce la infraestructura desacoplada de **Restore Points**: snapshots nombrados que encapsulan un `SessionSnapshot` (D69) completo, sin alterar Session (D65), Persistence (D66), Restore (D67), Autosave (D68) ni Snapshots (D69).

Al cierre de D70 existirá un módulo independiente bajo `src/components/session/restorePoints/` con:

- contratos Freeze (`RestorePoint`, `RestorePointId`, `RestorePointOrigin`, `RestorePointMetadata`, `RESTORE_POINT_SCHEMA_VERSION`)
- Factory (`createRestorePoint` → `createSessionSnapshot` + wrap)
- Registry in-memory Map SSOT (`create` / `get` / `remove` / `clear` / `list` / `count`)
- Serializer / Deserializer puros (schema gate; reutilizan serdes D69)
- barrel público exclusivo `@/components/session/restorePoints`
- suite de validadores + certificación

**SessionSnapshot permanece el dueño del estado serializado.** Restore Point solo agrega identidad nombrada + metadata funcional. No hay UI, historial visual, timeline, undo, versionado, branching, diff ni persistencia nueva.

Espejo de capas:

| Serie | Dirección |
|-------|-----------|
| **D65** | Session runtime (Registry SSOT) |
| **D69** | SessionState → SessionSnapshot |
| **D70** | SessionSnapshot → RestorePoint (named wrapper) |

```text
Session (D65)
        ↓
SessionSnapshot (D69)     // estado serializado inmutable
        ↓
RestorePoint (D70)        // snapshot nombrado + metadata
```

**Prohibido:** `RestorePoint → SessionRegistry` (imports o llamadas).  
**Obligatorio:** siempre utilizar Snapshot existente / creado vía API D69.

## 2. Objetivos

### 2.1 Objetivo primario

Crear la **infraestructura desacoplada de Restore Points** sobre Session Snapshots, certificada y lista para historial / recuperación avanzada futura (**D71+**) **sin refactorizar** el código certificado de D65–D69.

### 2.2 Objetivos específicos

1. Congelar la API de Restore Points (Types, Metadata/Origin, Factory, Registry surface, ser/deser, schema).
2. Encapsular siempre un `SessionSnapshot` completo (composición); nunca duplicar ownership de `SessionState`.
3. Factory congelada: `createRestorePoint` → `createSessionSnapshot(..., SnapshotReason.RESTORE_POINT)` → wrap.
4. Registry surface exacta; **HR-rp-snapshot-identity** (snapshot jamás reemplazable tras `create`).
5. Ser/deser puro reutilizando `serializeSessionSnapshot` / `deserializeSessionSnapshot`; sin Adapter / IDB / Bridge.
6. Aislar barrel (`session/index` y `snapshots/index` no re-exportan restorePoints) e imports.
7. Certificar boundaries y compatibilidad total con D65–D69 (`validate:d70-gate` cascada).

### 2.3 No-objetivos (esta serie)

Ver §8 Fuera de alcance.

## 4. Arquitectura

### 4.1 Ubicación del módulo (previsto D70.1+)

```text
    RestorePointMetadata.ts

    RestorePointSerializer.ts
    RestorePointDeserializer.ts

```

**Exactamente estos 7 archivos.** No crear archivos adicionales bajo `restorePoints/`.

**Reglas de colocación:**

- **Nunca** dentro de `windows/` / `tabs/` / `content/` / `series/`
- **Nunca** mezclado en el núcleo Session (archivos D65 top-level)
- **Nunca** dentro de `snapshots/`, `persistence/`, `restore/`, `autosave/`
- Módulo **completamente separado** bajo `session/restorePoints/`
- **No** se re-exporta desde `src/components/session/index.ts`
- **No** se re-exporta desde `src/components/session/snapshots/index.ts`
- Entrada pública exclusiva: `@/components/session/restorePoints`

### 4.2 Separación de responsabilidades

| Componente | Responsabilidad única | No hace |
|------------|----------------------|---------|
| **RestorePointTypes** | Contratos Freeze (`RestorePoint`, ids, schema, Record) | I/O, React, Registry logic |
| **RestorePointMetadata** | `RestorePointOrigin` + `RestorePointMetadata` Freeze | Snapshot state; SessionRegistry |
| **RestorePointFactory** | `createRestorePoint` → D69 factory + wrap | Construir snapshots a mano; mutar Registry |
| **RestorePointRegistry** | Map SSOT · surface Freeze | `update` / `replace` / `rename` / sustituir snapshot |
| **Serializer / Deserializer** | Record schema-versioned · reutiliza serdes D69 | Adapter / IDB / Bridge |
| **restorePoints/index.ts** | Única exportación pública del módulo | Re-export Session / Snapshots / Persistence / Restore / Autosave |

### 4.3 Pipeline certificado

```text
Caller (sessionId + state + name + …)
        ↓
createRestorePoint(options)
        ↓
createSessionSnapshot({ sessionId, state, reason: RESTORE_POINT })   // D69 only
        ↓
wrap → RestorePoint { id, name, description?, createdAt, origin, snapshot, metadata }
        ↓
registry.create(restorePoint)
        ↓
(optional) serializeRestorePoint → RestorePointRecord
        ↓
(optional) deserializeRestorePoint → RestorePoint
```

### 4.4 Diagrama de dependencias

```text
Caller
        │
        ▼
┌──────────────────────────────┐
│ RestorePointFactory          │
│  → createSessionSnapshot     │────► @/components/session/snapshots (D69 FREEZE)
│  → wrap RestorePoint         │
└────────────┬─────────────────┘
             │
             ▼
┌──────────────────────────────┐
│ RestorePointRegistry (Map)   │
│  create/get/remove/clear/    │
│  list/count                  │
└────────────┬─────────────────┘
             │
             ▼
┌──────────────────────────────┐

│  → deserializeSessionSnapshot│

PROHIBIDO: flechas hacia SessionRegistry / Provider / Context / Bridge /
           persistence / restore(D67) / autosave / IndexedDB
```

### 4.5 Integración Provider

**Ninguna en D70.**  
`SessionProvider` permanece Freeze. A diferencia de D69.7 (private `snapshotStoreRef`), D70 **no** autoriza wiring en Provider. Restore Points es capa de dominio pura / library-first.

### 4.6 Semántica Freeze — identidad del snapshot

```text
create(restorePoint)
  → almacena clone defensivo
  → el SessionSnapshot embebido queda FIJO para ese RestorePointId

get / list
  → clones defensivos (sin refs mutables vivas)

remove / clear
  → eliminan el Restore Point completo
  → NUNCA “reemplazan” solo el snapshot

PROHIBIDO:
  update(id, patch)
  replace(id, restorePoint)
  rename(id, name)
  mutate(...)
  replaceSnapshot(id, snapshot)
```

## 5. API Freeze

Toda superficie listada aquí queda **congelada** en D70.0. Implementación (D70.1+) debe respetarla exactamente. **Sin implementación en D70.0.**

### 5.1 RESTORE_POINT_SCHEMA_VERSION

```ts
const RESTORE_POINT_SCHEMA_VERSION = 1 as const;
```

### 5.2 RestorePointOrigin / RestorePointMetadata

```ts
const RestorePointOrigin = {
  MANUAL: "MANUAL",
  SYSTEM: "SYSTEM",
  IMPORT: "IMPORT",
} as const;

type RestorePointOrigin =
  (typeof RestorePointOrigin)[keyof typeof RestorePointOrigin];

type RestorePointMetadata = {
  readonly tags?: readonly string[];
  readonly correlationId?: string;
};
```

### 5.3 RestorePoint / RestorePointRecord

```ts
type RestorePointId = string;

interface RestorePoint {
  readonly id: RestorePointId;
  readonly name: string;
  readonly description?: string;
  readonly createdAt: number;
  readonly origin: RestorePointOrigin;
  readonly snapshot: SessionSnapshot; // encapsulación D69 completa
  readonly metadata: RestorePointMetadata;
}

interface RestorePointRecord {
  readonly schemaVersion: typeof RESTORE_POINT_SCHEMA_VERSION;
  readonly id: RestorePointId;
  readonly name: string;
  readonly description?: string;
  readonly createdAt: number;
  readonly origin: RestorePointOrigin;
  readonly snapshot: SessionSnapshotRecord; // vía serializeSessionSnapshot
  readonly metadata: RestorePointMetadata;
}
```

### 5.4 Factory

```ts
type CreateRestorePointOptions = {
  readonly sessionId: SessionId;
  readonly state: SessionState;
  readonly name: string;
  readonly description?: string;
  readonly origin: RestorePointOrigin;
  readonly metadata?: RestorePointMetadata;
};

createRestorePoint(options: CreateRestorePointOptions): RestorePoint;
```

Pipeline obligatorio:

```text
createRestorePoint()
  → createSessionSnapshot({ sessionId, state, reason: SnapshotReason.RESTORE_POINT })
  → wrap { id, name, description?, createdAt, origin, snapshot, metadata }
```

**Prohibido:** construir `SessionSnapshot` manualmente · omitir `RESTORE_POINT` · llamar SessionRegistry.

### 5.5 RestorePointRegistry

```ts
type RestorePointRegistry = {
  create(restorePoint: RestorePoint): boolean;
  get(id: RestorePointId): RestorePoint | undefined;
  remove(id: RestorePointId): boolean;
  clear(): void;
  list(): readonly RestorePoint[];
  count(): number;
};

createRestorePointRegistry(): RestorePointRegistry;
```

**Surface pública EXACTA** — nada más.  
**Prohibido:** `update` / `replace` / `rename` / `mutate` / cualquier sustitución del snapshot embebido.

### 5.6 Serializer / Deserializer

```ts
serializeRestorePoint(restorePoint: RestorePoint): RestorePointRecord;
deserializeRestorePoint(record: RestorePointRecord): RestorePoint;
```

- Serializer embebe snapshot vía `serializeSessionSnapshot`
- Deserializer gatea `schemaVersion === RESTORE_POINT_SCHEMA_VERSION` y rehidrata snapshot vía `deserializeSessionSnapshot`
- Puros — sin I/O

### 5.7 Barrel público (`restorePoints/index.ts`)

**Allowlist (congelada — prospectiva):**

- `RESTORE_POINT_SCHEMA_VERSION`
- `RestorePointId` · `RestorePoint` · `RestorePointRecord`
- `RestorePointOrigin` · `RestorePointMetadata`
- `CreateRestorePointOptions` · `createRestorePoint`
- `RestorePointRegistry` · `createRestorePointRegistry`
- `serializeRestorePoint` · `deserializeRestorePoint`

**Prohibido:**

- `export *`
- Re-export desde `session/index.ts` o `snapshots/index.ts`
- Re-exports de persistence / restore / autosave / SessionProvider / Registry
- Hooks React / UI

### 5.8 Compatibilidad D65–D69 (intacta)

## 6. Hard Rules

| ID | Regla |
|----|-------|
| **HR-rp-on-snapshot** | RestorePoint siempre encapsula `SessionSnapshot`. Nunca escribe SessionRegistry. |
| **HR-rp-immutable** | Todos los campos `readonly`. Sin mutate del payload tras creación. |
| **HR-rp-snapshot-identity** | El `SessionSnapshot` encapsulado es inmutable y **nunca puede ser reemplazado** después de `create()`. El Registry puede eliminar o listar Restore Points, pero **nunca sustituir** el snapshot asociado. |
| **HR-rp-reason** | Factory utiliza `SnapshotReason.RESTORE_POINT` exclusivamente al crear el snapshot encapsulado. |
| **HR-rp-no-provider** | Cero cambios a SessionProvider / Context / SessionAPI. |
| **HR-rp-no-storage** | Sin Adapter. Sin IndexedDB. Sin Bridge. Solo ser/deser puro. |
| **HR-rp-barrel-isolation** | Barrel independiente; `session/index` y `snapshots/index` **must NOT** export `restorePoints/*`. Sin `export *`. |
| **HR-rp-consume-only** | Consumir D69 sin modificarlo. `validate:d69-gate` permanece PASS. |
| **HR-rp-registry-surface** | Registry expone solo `create/get/remove/clear/list/count`. Sin `update` / `replace` / `rename` / `mutate`. |
| **HR-rp-import-isolation** | `restorePoints/*` no importa Registry / Provider / Context / Bridge / `persistence/*` / `restore/*` / `autosave/*` / windows / tabs / content / series / IndexedDB / React. Solo `@/components/session/snapshots` + internos `./`. |
| **HR-rp-no-ui** | Sin UI / botones / panel / timeline en D70. |
| **HR-d65-d69-compat** | Gates previos permanecen PASS; cero refactor de código certificado D65–D69. |
